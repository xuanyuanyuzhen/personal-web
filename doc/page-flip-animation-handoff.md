# 翻页动画接手记录

## 1. 当前结论

当前翻页动画已经从“整页 3D 旋转”改为“移动折痕 + 页面裁切 + 目标页快照”的卷页模型。

- 当前稳定提交：`e1ec8b4 fix(web): implement directional curved page turns`
- 当前分支：`codex/ui-layout-i18n-polish`
- 单次动画时长：`620ms`
- 动画方向由顶部一级导航顺序决定，与跨越页面数量无关，始终只播放一次。

## 2. 最终目标与验收要求

### 翻页方向

- 目标页面位于当前页面右侧：右边书页向左翻。
- 目标页面位于当前页面左侧：左边书页向右翻。
- 文章详情与文章列表视为同一导航位置，不应因同组路由切换重复翻页。

### 书页内容

- 折痕尚未经过的区域显示当前页正面内容。
- 翻起书页的背面显示目标页内容，而不是当前页或空白背景。
- 折痕经过后，目标页在下层逐渐完整显现。
- 进入页面时即使发生空状态、加载态和真实数据切换，翻页过程中的画面也不能跟着跳变。

### 视觉与布局

- 折痕必须是贯穿整页、会横向移动的竖向弧形折痕。
- 禁止整页围绕中轴硬翻，也不能退化成简单淡入淡出。
- 页面保持条纹纸张背景，翻起区域不能变成纯色空白。
- 两侧棕色书皮始终存在，不只在动画期间出现。
- 页内容保留舒适边距，不能贴着书皮或内容边缘翻动。
- 顶部导航栏不参与翻页，动画前后内容位置不能下移或跳动。
- 看板娘保持固定可见。
- 中文、英文、日文以及日间、夜间主题均需保持可读和无横向溢出。

### 节奏与交互

- 动画时长控制在 `500–650ms`，当前使用 `620ms`。
- 使用“起手较快、落地较慢”的非对称缓动。
- 快速连续点击导航时，新动画要抢占旧动画，不能叠加或误清理新页面。
- 明确触发的翻页在 `prefers-reduced-motion: reduce` 环境下仍保留；其他普通动效继续遵守减少动画设置。

## 3. 曾遇到的问题与根因

### 跨页越多，动画越久

旧实现按导航距离重复播放翻页，导致等待感明显。

解决：导航距离只用于判断方向，动画固定只播放一次。

### 只有淡入淡出，没有翻页感

过度追求只使用 `transform + opacity` 后，页面切换退化为普通淡入淡出，没有折痕和书页层次。

解决：保留必要的 `clip-path` 几何裁切，并增加独立折痕层和目标页背面层。

### 整页围绕中轴旋转

将离场页面设置为 `transform-origin: center` 并执行 `rotateY`，视觉上像硬卡片绕中轴翻转，不像书页从外侧掀起。

解决：取消整页 3D 旋转；通过移动裁切边界让当前页从对应外侧逐渐减少。

### 折痕固定在最左、最右或中间

仅设置固定旋转轴或固定伪元素，折痕不会随翻页过程移动。

解决：当前页裁切、背面裁切和折痕位置使用同一时间轴，从外侧向另一侧同步移动。

### 背面仍显示当前页或空白

单靠离场 DOM 和伪元素无法在书页背面绘制目标页面真实内容。

解决：目标页面进入时克隆两份冻结快照：一份作为下层目标页，一份裁切成翻起书页的背面带状区域。

### 数据加载导致动画内容变化

目标组件在动画期间可能从空状态切换为接口数据，直接使用实时 DOM 会产生闪动和错位。

解决：动画开始时冻结目标页快照；真实目标页在动画期间保持透明，动画结束后一次性接管显示。

### 内容明显下移

离场页绝对定位范围与 `.site-main` 的内边距、导航高度不一致，导致动画层与正常页面坐标不同。

解决：所有动画层统一相对于 `.site-main` 定位，桌面使用 `24px` 页边距，移动端使用 `16px` 页边距；导航栏始终位于动画容器之外。

### 动画卡顿和视觉噪声

早期同时动画化 `filter`、`mix-blend-mode`、动态阴影、缩放和多层高光，触发大量重绘且焦点混乱。

解决：移除滤镜、混合模式、动态边界阴影和整页缩放；主要保留裁切、透明度和一条折痕渐变。

### 快速反向点击会清除新动画

旧过渡被取消时仍会执行清理回调，可能误删刚创建的新目标页快照。

解决：快照记录所属目标元素；旧过渡的取消或结束回调只有在所有者匹配时才能清理当前快照。

### Vue 过渡钩子时序错误

`before-enter` 阶段目标节点尚未可靠挂载到 `.site-main`，无法创建动画覆盖层；将进入动画设为 `none` 又会让 `after-enter` 立即执行并清掉快照。

解决：在 `enter` 阶段创建快照，并用同为 `620ms` 的 `page-turn-target-hold` 动画维持目标页生命周期。

## 4. 当前实现结构

翻页期间从下到上共有四层：

| 层级 | 元素                         | 内容与职责                                 |
| ---- | ---------------------------- | ------------------------------------------ |
| 1    | `.page-turn-target-snapshot` | 冻结的目标页，位于最下层，避免数据更新跳变 |
| 2    | `.page-leave-active`         | 当前页正面，沿移动弧形边界逐渐被裁掉       |
| 3    | `.page-turn-back-snapshot`   | 目标页快照的窄带裁切，作为翻起书页的背面   |
| 4    | `.page-turn-crease`          | 贯穿页面的竖向渐变折痕，和裁切边界同步移动 |

真实进入页面使用 `.page-enter-active` 和 `page-turn-target-hold` 暂时保持透明。动画结束后删除三层辅助快照，真实页面立即接管。

## 5. 方向与动画映射

导航顺序定义在 `apps/web/src/composables/usePageFlip.ts`：

`home → thoughts → essays → photos → messages → about`

- `toIndex > fromIndex`：`forward`，调用右侧向左的 `page-curl-*-forward` 动画。
- `toIndex < fromIndex`：`backward`，调用左侧向右的 `page-curl-*-backward` 动画。
- 索引相同或无法识别：不触发翻页。

新增一级导航页面时，必须同步更新 `pageOrder` 和 `pagePathOrder`。

## 6. 关键文件

- `apps/web/src/composables/usePageFlip.ts`
  - 维护导航顺序、方向、`620ms` 时长和快速导航清理时机。
- `apps/web/src/composables/usePageTurnSnapshot.ts`
  - 创建目标页底层快照、书页背面快照和折痕层。
  - 移除快照中的 `id`，设置 `aria-hidden` 和 `inert`，防止重复交互和无障碍干扰。

  - 定义正面、背面、折痕、移动端尺寸、夜间变量和减少动画环境下的显式翻页覆盖。

## 7. 性能取舍

当前没有使用 `filter`、`mix-blend-mode`、整页缩放和动态 `box-shadow`。

为实现真实的移动弧形边界，正面和背面使用了可插值的多点 `clip-path: polygon(...)`；折痕层会动画化位置。它们比纯 `transform` 成本高，但参与动画的元素数量固定、时长短，当前桌面和移动布局可接受。

如果未来仍需进一步提升低端设备性能，优先顺序是：

1. 将折痕位置改为容器内纯 `transform` 位移。
2. 将多点裁切改为预渲染 SVG mask，并只移动 mask。
3. 降低弧形采样点数量，而不是重新加入滤镜或多层阴影。

## 8. 已知边界

- 当前弧线由多点多边形近似，并非物理纸张模拟。
- 背面内容是真实目标页快照的窄带裁切，但没有逐像素透视形变。
- 如果要达到小说阅读器中的高精度纸张拉伸、卷曲和光照效果，应评估 Canvas/WebGL 或 SVG 位移贴图；不建议继续堆叠复杂 CSS 滤镜。
- 页面根节点若依赖实时脚本状态、Canvas 或视频，`cloneNode` 快照不能完整冻结其绘制内容，需要单独提供静态占位或截图方案。

## 9. 回归检查清单

每次修改后至少检查：

1. 首页向随笔跳转：右页向左翻，当前页逐渐减少。
2. 随笔向首页跳转：左页向右翻，方向完全镜像。
3. 翻起书页背面显示目标页内容，折痕后下层也是目标页。
4. 翻页中加载数据：动画快照不发生内容跳变。
5. 快速连续点击左右导航：最新动画正常接管，无残留快照。
6. 中文、英文、日文在日间和夜间主题下无横向溢出。
7. 书皮、条纹纸张、导航栏、页边距和看板娘在动画前后保持稳定。
8. 动画结束后 DOM 中不存在 `.page-turn-*-snapshot` 和 `.page-turn-crease` 残留。

验证命令：

```bash
pnpm --filter @yuer/web test
pnpm --filter @yuer/web build
pnpm lint:style
```

浏览器视觉验证时，自动化截图可能错过 `620ms` 的中间帧。调试可以临时延长 `pageFlipDuration`，但提交前必须恢复为 `620`，并确认相关测试断言未被修改。
